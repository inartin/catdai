# Admin

## Stage
Implemented as admin dashboard with direct registered-user package adjustment.

## Access
- `/admin/login?key=...` requires `ADMIN_LOGIN_KEY`.
- Password is checked against `ADMIN_PASSWORD`.
- `/api/admin/auth` blocks an IP after 5 failed login attempts for 15 minutes and returns `Retry-After`.
- In production, admin login throttling requires Redis and fails closed with `503` if Redis is unavailable, so failed attempts are shared across app processes.
- Admin login does not trust `x-forwarded-for` or `x-real-ip`; `cf-connecting-ip` is used only when `ADMIN_TRUST_CF_CONNECTING_IP=true` after direct-origin access is blocked at the infrastructure layer.
- Successful login sets an httpOnly signed `admin_token` session cookie that expires after 12 hours.
- `ADMIN_TOKEN` is used as the server-side HMAC signing secret and is not stored directly in the cookie.
- All `/admin` and `/api/admin` routes require a valid signed `admin_token` session in `src/proxy.js`.
- Protected `/api/admin/*` data routes also verify the `admin_token` cookie inside each route before returning cached data or using `SUPABASE_SERVICE_KEY`.

## Cadastru
`/admin/cadastru` starts with an all-time database overview, followed by offline search:
- A leading unique cadastral numbers card covers all property types, followed by separate cards for verified apartment buildings, apartment/unit records (including references), units with details, and other properties. Shared building registry duplicates are counted once in the overall unique-number total.
- Per-building coverage bars for cadastral details, nearby places, public transport and municipal reports, with saved/missing and fresh/expired counts. Address aliases are deduplicated; reports apply only to Chișinău. Coverage reads the dedicated durable stores and excludes explicitly incomplete/stale source responses; expired saved snapshots still count as stored.
- Whole-building collection results: harvested, partial harvest, or not harvested yet. These reflect saved collection metadata, not the worker's live queue; a harvested response does not prove a complete apartment inventory.
- City breakdown separates buildings, apartments/units and other properties; missing cities appear as Unknown city.
- Clicking a city opens all stored land, building and apartment/unit records, including collected references and units with no search history, with address-search counters overlaid. The Apartments column counts stored units by unique cadastral number; Land parcels counts stored land records. Address rows expand into typed property rows (land, building, apartment or other property), with cadastral numbers. Addresses sort by searches, then last searched, in pages of 50; expanding a building shows its stored units in apartment-number order. Units without an apartment number display their cadastral number. Unsearched rows show zero counters and no last-search date. Search-only apartments are labeled separately and do not increase the stored apartment count; searches without an apartment have a separate `Without apartment` row.
- Inventory comes from `cadastru_records` and `cadastru_buildings`, including expired snapshots. Shared building links provide canonical addresses; legacy records use their exact stored address. Units with no usable address remain visible under their building cadastral identifier. City, road type, street and house suffix remain distinct; exact dictionary aliases normalize known street spellings. Search counts use only retained address-search events, including cached and unsuccessful searches; collector activity and number searches do not create address-search counts. Registered users are deduplicated across a building; repeat uses are searches after the first at each level. Ambiguous apartment labels keep search counts separate unless the event identifies the stored cadastral number. Anonymous searches and authenticated searches after login remain separate events.
- `GET /api/admin/cadastru-storage/address-reuse?city=...&offset=...` checks admin authentication before reads/cache access, reads every inventory/event page, and caches metadata for five minutes for pagination. Opening or reopening a city fetches a fresh database snapshot; Hard refresh reloads the open city. The table shows its snapshot timestamp and does not update live while left open. Failed reads show unavailable with Retry rather than partial/search-only inventory. Unusable historical search addresses are excluded and counted when their city is known. No schema migration or new tracking is required.
- Address-reuse regression check: `pnpm exec node --experimental-vm-modules scripts/test-admin-cadastru-address-reuse.mjs`.
- Building address labels omit the selected city. Stored apartment counts include collected references; they describe saved inventory, not a guaranteed complete physical apartment inventory.

`/api/admin/cadastru-storage` reads counting metadata only, retains admin authentication, a five-minute cache and Hard refresh. Any failed database read shows unavailable rather than misleading zero/partial totals. The overview is independent of dashboard period filters. Regression check: `pnpm exec node --experimental-vm-modules scripts/test-admin-cadastru-storage-stats.mjs`.

## MAIB refunds
The user transaction list includes both processors and labels sandbox rows. MAIB rows support full refunds with reason and amount confirmation, plus status refresh. The API requires the admin session and same-origin requests, calculates the remaining refundable amount, and reserves an attempt before contacting MAIB. Created/Requested stay pending; Accepted removes only unused credits from that order. Rejected allows a deliberate new attempt; Manual/unknown require review and block resubmission. External partial refunds are recorded without reducing credits until fully refunded. Production paid-user and attribution reports exclude MAIB sandbox rows. See [MAIB payments](maib-payments.md).
