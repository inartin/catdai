# SEO Audit - 2026-05-31

## Scope
- Audited the local Next.js SEO implementation, existing docs, sitemap/robots setup, public route metadata, localized routes, and selected live production responses for `https://catdai.md`.
- No app code was changed.
- Existing uncommitted files were not modified: `docs/valuation.md`, `src/app/evaluare/page.js`, `src/locales/ro.json`, `src/locales/ru.json`.

## Short Answer
The app is not blocked from Google by a hard technical issue. `robots.txt` allows search crawling, the sitemap is available, the main pages return `200`, and Google has crawled the homepage.

The low or missing keyword traffic is more likely caused by a small indexable footprint, weak keyword-specific metadata, limited crawlable content for the exact searches users make, and likely low domain authority/off-site signals. There are also a few technical SEO issues worth fixing, but they look like ranking and clarity issues, not complete deindexing issues.

## Main Problems

### 1. The site has too few indexable pages for organic discovery
Status: partially fixed ✅

The sitemap currently has only a small set of generic pages plus four shared result pages. There are no dedicated crawlable pages for high-intent searches such as:
- `estimare pret apartament chisinau`
- `evaluare apartament chisinau`
- `pret metru patrat chisinau`
- `pret apartament botanica`
- `cat costa un apartament in chisinau`
- Russian equivalents for `оценка квартиры кишинев`, `цена квартиры кишинев`, `цена за м2 кишинев`.

For Google, one homepage and one form page are usually not enough to compete, even in a smaller local market. The app has useful market data, but most of that value is behind interactive flows and API-driven result states, not static pages that Google can rank for many queries.

Fixed so far:
- Added four dedicated Botanica pages for apartment price searches in Romanian and Russian.
- Added old-building and new-building variants for the same 2-room, 50 m², eurorepaired profile.
- Added those pages to the sitemap and linked them from FAQ.

### 2. Homepage metadata is brand/generic, not query-targeted
Live homepage metadata:
- Title: `Catdai - Înțelege piața imobiliară. Decide corect.`
- Description: `Pentru vânzători, cumpărători și chirie: vezi prețuri realiste, potențial de chirie lunară și analiza pieței pe criteriile tale.`

This is understandable product copy, but it does not strongly target the exact query the user gave: `estimare cost apartament chisinau catdai`.

Recommended direction:
- Title should include the core product/query: `Estimare preț apartament Chișinău | Catdai`.
- Description should include the actual user intent: online estimate, apartment price, Chișinău, comparable listings, market price.

### 3. Indexable estimator/result titles are vague
Current production examples:
- `/ro/estimeaza`: `Datele Analizei | Catdai`
- `/ro/evaluare`: `Evaluarea Pietii | Catdai`
- `/ru/estimeaza`: `Данные анализа | Catdai`
- `/ru/evaluare`: `Анализ Рынка | Catdai`

These titles do not say "apartament", "preț", "estimare", "Chișinău", "квартира", "цена", or "Кишинев". They are weak signals for search intent.

Recommended direction:
- `/ro/estimeaza`: `Estimare preț apartament Chișinău | Catdai`
- `/ro/evaluare`: `Analiză preț apartament Chișinău | Catdai`
- `/ru/estimeaza`: `Оценка цены квартиры в Кишиневе | Catdai`
- `/ru/evaluare`: `Анализ цены квартиры в Кишиневе | Catdai`

### 4. Russian pages inherit a Romanian meta description
The Russian localized pages have Russian titles, but still use the global Romanian description.

Confirmed live example:
- `/ru/estimeaza` title is Russian.
- `/ru/estimeaza` description is Romanian.
- `/ru/evaluare` title is Russian.
- `/ru/evaluare` description is Romanian.

This weakens language targeting and can reduce click-through rate for Russian searchers.

### 5. The homepage lacks canonical and hreflang metadata
The localized deeper pages have canonical and alternate language tags. The root homepage does not currently expose a canonical link or alternate language links.

This is not a deindexing problem, but it leaves Google with weaker locale signals for the main page. If `/` remains the Romanian homepage, add a canonical for `/` and language alternates for the intended home URLs. If separate `/ro` and `/ru` home URLs should be the SEO targets, add real localized home routes and put them in the sitemap.

### 6. `/ro/evaluare` and `/ru/evaluare` are indexable but are not strong landing pages
The evaluation page is a client-driven result shell. Without valid query params, the current code routes the user back to `/`. That means Google can index a URL that has little stable standalone content.

Options:
- Keep `/ro/evaluare` indexable, but add static explanatory content that is useful before a result is loaded.
- Or remove `/ro/evaluare` and `/ru/evaluare` from the sitemap and noindex them, then use `/ro/estimeaza`, `/ru/estimeaza`, FAQ, market pages, and shared `/imobil/[slug]` pages as the SEO entry points.

### 7. Live production appears behind the latest local copy changes
The live homepage text seen by Google still showed older wording: `Nu ghici prețul - verifică piața.`

The local uncommitted Romanian locale currently has a stronger H1: `Verifică prețul real al unui apartament`. That is a better SEO direction, but it was not confirmed as deployed in production during this audit.

### 8. No static market pages exist for the data the app already has
Status: partially fixed ✅

The app already has market trend and price APIs, but there are no indexable market pages like:
- `/ro/piata-imobiliara/chisinau`
- `/ro/preturi-apartamente/chisinau`
- `/ro/preturi-apartamente/chisinau/botanica`
- `/ru/rynok-nedvizhimosti/kishinev`

This is the biggest product SEO gap. Google ranks pages, not API capabilities. The app can calculate useful data, but organic search needs crawlable pages that answer search intent before the user submits a form.

Fixed so far:
- Added the first static market-analysis page set for Botanica.
- Pages use saved local valuation data and human-readable explanatory text.
- Pages now compare old-building vs new-building variants through internal links.

## Likely Non-Code Causes
- Domain authority is probably low. A newly launched or low-link domain can be indexed but not rank even for long-tail queries.
- Search Console "indexed" does not mean "ranking". It only means Google can store the URL. Ranking still depends on content relevance, authority, internal links, external links, freshness, and user intent match.
- If GSC shows zero queries, verify date range, property type, sitemap submission, and whether the inspected canonical URL is the same one in the sitemap.

## Conclusion
This does not look like "Google cannot index a Next.js app". The app is crawlable enough for Google to discover it.

The core SEO problem is that Catdai currently exposes too little crawlable, keyword-focused content. The interactive estimator is useful for users, but Google needs static pages with exact search intent, localized metadata, internal links, and authority signals. Fix metadata first, then create real market and guide pages around the data the app already has.
